# Maintaining this profile

This repo is the special `sushil-choudhary/sushil-choudhary` GitHub profile
repository — its `README.md` renders on your GitHub profile page. This file
documents how the automation works and how to update content later.

## Repository structure

```
README.md                          the profile page itself
assets/
  badges/                          hero pill buttons (Portfolio/GitHub/LinkedIn/Email), dark+light
  icons/                           small glyphs for links Simple Icons can't serve (globe, mail, linkedin)
  sections/{dark,light}/           custom section-header banners (01-about.svg ... 08-experience.svg)
  cards/                           GitHub telemetry — stats, top-langs, streak, activity-graph (dark+light),
                                    plus snapshot-{dark,light}.svg (the static career-stats card)
  snake-{dark,light}.svg           contribution snake, regenerated daily
scripts/
  gen_section_headers.py           regenerates assets/sections/**
  gen_badges.py                    regenerates assets/badges/**
  gen_icons.py                     regenerates assets/icons/**
  gen_snapshot_card.py             regenerates assets/cards/snapshot-*.svg
  gen_placeholders.py              writes "not generated yet" placeholders for CI-owned assets (never overwrites real ones)
.github/workflows/
  update-stats.yml                 daily: refreshes assets/cards/{stats,langs,streak,activity-graph}-*.svg
  generate-snake.yml               daily: refreshes assets/snake-*.svg
```

## What's static vs. what's generated by CI

- **Static, hand-authored** (edit the script, then re-run it): section headers,
  hero badges, icons, the snapshot card. These encode career facts and branding,
  not live GitHub data — nothing regenerates them automatically.
- **CI-refreshed daily**: `assets/cards/stats-*.svg`, `langs-*.svg`,
  `streak-*.svg`, `activity-graph-*.svg`, and `assets/snake-*.svg`. These are
  fetched from external generators or GitHub's contribution API and committed
  as static files, so the README always renders from a known-good copy even
  if the upstream service is briefly down.

## GitHub repository setup

1. Push this repository's contents to `github.com/sushil-choudhary/sushil-choudhary`
   (this exact name — GitHub only renders a profile README for a repo matching
   your username).
2. In **Settings → Actions → General → Workflow permissions**, select
   **"Read and write permissions"**. Both workflows commit back to the repo
   using the built-in `GITHUB_TOKEN`; without write permission the commit step
   fails.
3. No repository secrets are required. Everything uses the public,
   unauthenticated instances of github-readme-stats / github-readme-streak-stats
   / github-readme-activity-graph, and `Platane/snk` reads your public
   contribution graph directly — no token needed for a public profile.
4. After the first push, run both workflows once manually
   (**Actions → [workflow name] → Run workflow**) instead of waiting for the
   next scheduled run, so the placeholder SVGs get replaced immediately.

## How to update content later

- **New job / promotion / years of experience**: edit the `STATS` list in
  `scripts/gen_snapshot_card.py` and the Experience table in `README.md`
  directly, then re-run `python3 scripts/gen_snapshot_card.py`.
- **New featured platform / project**: edit the tables in `README.md`
  directly (Featured Platforms / Other Platforms / Public Repositories) — these
  are plain Markdown/HTML tables, no generator involved.
- **New public repo you want listed with live star/fork counts**: add a row to
  the Public Repositories table using the same `img.shields.io/github/stars/...`
  and `.../forks/...` pattern already used there — those badges are always live
  (not cached), so no CI change is needed.
- **New/changed tech stack entry**: add a badge in the Tech Stack table using
  `https://img.shields.io/badge/<Label>-0D1117?style=for-the-badge&logo=<simple-icons-slug>&logoColor=<hex>`.
  Verify the logo slug resolves first: `curl -o /dev/null -s -w "%{http_code}" https://cdn.simpleicons.org/<slug>`.
- **Rebranding / new section / renamed section**: edit `SECTIONS` in
  `scripts/gen_section_headers.py`, re-run it, and update the corresponding
  `<picture>` block in `README.md`.

## External services used (and their failure modes)

| Service | Used for | If it goes down |
|---|---|---|
| github-readme-stats (vercel.app, public instance) | stats + top-languages cards | Last committed SVG keeps rendering; next scheduled CI run retries and the workflow step fails loudly (SVG-emptiness check) instead of committing a blank card. |
| github-readme-streak-stats (demolab.com) | streak card | Same as above. |
| github-readme-activity-graph (vercel.app) | activity graph | Same as above. |
| Platane/snk GitHub Action | contribution snake | Same as above — the action itself reads GitHub's own contribution API, so this only breaks if GitHub's API or the action changes. |
| Google Fonts (Raleway) | typography inside the generated SVGs | Falls back to `Segoe UI` / system sans-serif — every SVG declares an explicit fallback stack. |
| shields.io | tech-stack badges, GitHub star/fork counts | These are hotlinked directly in `README.md` (not mirrored), so a shields.io outage would show broken images until it recovers. This is standard practice — shields.io has very high uptime and is the same service almost every GitHub profile README depends on. |

## Known limitations

- No npm packages, Medium/Dev.to/LeetCode/Peerlist profiles, or open-source
  repos with real stars exist for this account today — so the profile doesn't
  claim any. Add those sections yourself once such a profile/package exists.
- The public (non-authenticated) stats/streak/activity-graph endpoints only
  count **public** contributions. If private-repo activity should count too,
  those three services would need to be self-hosted with a personal access
  token — not set up here to avoid storing a broad-scope PAT for a cosmetic
  feature.
- The `sushil-choudhary/sushil-choudhary` repository currently also hosts the
  React portfolio app (see the sibling project). If you fully replace that
  repo's contents with this profile system, make sure the portfolio app's
  deployment (Vercel) points at its own separate source rather than this repo.
